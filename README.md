# Vivi MCP

MCP-сервер, который даёт ИИ-агентам (Claude Code, Cursor, Devin и любым другим MCP-клиентам)
**смотреть дизайн в открытом файле Figma**: структуру нод, скриншоты, токены, ассеты, — и
выгружать из него картинки и иконки прямо в код проекта. А с версии 0.3 — **создавать и править
дизайн**: агент присылает JSON-спеку, плагин строит настоящие ноды Figma (auto-layout, текст,
фото, иконки), возвращает скриншот и замечания проверки макета; любое изменение откатывается.

Состоит из трёх частей:

- **Плагин Figma** (`plugin/`) — маленькое окно: держит связь с мостом и отвечает на запросы
  агента данными из открытого файла.
- **Мост** (`server/index.mjs`) — локальный WebSocket-сервер `ws://localhost:8787` между плагином
  и MCP-сервером.
- **MCP-сервер** (`server/mcp.mjs`) — то, что подключается к вашему агенту (stdio).

```
MCP-клиент ──stdio──> server/mcp.mjs ──WebSocket──> server/index.mjs ──WebSocket──> плагин Figma
 (агент)                                (мост, :8787)                                (открытый файл)
```

> Плагин не из каталога Figma: Figma запрещает плагинам ходить во внешние программы, поэтому
> работает связка «плагин + локальный мост», всё работает на вашей машине.

## Быстрый старт

**Нужно:** Node.js 20+ и Figma (десктоп) с возможностью подключать плагины разработчика.

1. Подключите MCP к агенту — клонировать ничего не нужно, пакет скачается сам (`npx`):

   Claude Code (один раз на машину, доступно во всех проектах):

   ```bash
   claude mcp add vivi-figma --scope user -- npx -y vivi-figma-mcp
   ```

   Любой другой клиент (Cursor, Devin, Windsurf…) — блок в его MCP-конфиге:

   ```json
   {
   	"mcpServers": {
   		"vivi-figma": {
   			"command": "npx",
   			"args": ["-y", "vivi-figma-mcp"]
   		}
   	}
   }
   ```

2. Один раз установите плагин в Figma. Команда скопирует плагин в постоянную папку `~/.vivi-figma/plugin` и покажет путь к манифесту:

   ```bash
   npx -y vivi-figma-mcp plugin
   ```

   В Figma: **Plugins → Development → Import plugin from manifest…** → выбрать этот файл.
3. Откройте нужный файл и запустите **Plugins → Development → Vivi MCP**. Окно плагина оставьте
   открытым: пока оно открыто, агент видит этот файл.

Мост запускать вручную не нужно — MCP-сервер сам стартует его в фоне (лог — `~/.vivi-figma/bridge.log`). Проверка: попросите агента вызвать `figma_status` — в ответе будет имя
открытого файла. Ошибка «плагин не подключён» — не запущен плагин; «мост не отвечает» —
смотрите этот лог.

### Из исходников

```bash
git clone https://github.com/Razavik/Vivi-Figma.git
cd Vivi-Figma
npm run setup        # зависимости + сборка плагина
claude mcp add vivi-figma --scope user -- node /путь/к/Vivi-Figma/server/mcp.mjs
```

Манифест плагина — `plugin/manifest.json`.

## Инструменты

| Инструмент            | Что делает                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------- |
| `figma_status`        | файл, страница, выделение, подключён ли плагин                                              |
| `figma_selection`     | структура выделенных нод                                                                    |
| `figma_outline`       | верхние фреймы страницы                                                                     |
| `figma_node`          | дерево ноды: размеры, auto-layout, цвета, шрифты, `box:[x,y,w,h]`, свойства векторов        |
| `figma_screenshot`    | PNG ноды (`scale`, `maxSize` до 4096); `region:[x,y,w,h]` — приблизить часть, `tiles:N` — нарезать длинную страницу на читаемые куски |
| `figma_review`        | одним вызовом: замечания lint по ноде + нарезка на куски (контраст над фото помечен `onPhoto`) |; `fix:true` чинит сетку 4/8 и мелкий кегль сам (с записью и откатом)
| `figma_search`        | поиск нод по имени или тексту, фильтр по типу                                               |
| `figma_assets`        | фото и иконки внутри ноды                                                                   |
| `figma_export`        | сохранить ноды файлами (PNG / JPG / SVG / PDF)                                              |
| `figma_export_assets` | одним вызовом выгрузить все фото и иконки блока; одинаковые файлы пишутся один раз          |
| `figma_tokens`        | цвета, шрифты, радиусы, отступы по частоте — для CSS-переменных                             |
| `figma_design_system` | локальные стили, переменные и компоненты файла                                              |

Несколько нод за один вызов: у `figma_node`, `figma_screenshot`, `figma_tokens` и `figma_assets` вместо `id` можно передать массив `ids` (у `figma_node` до 25, у скриншотов до 8, у остальных до 10) — результат придёт списком в том же порядке.

`figma_node` отдаёт у нод `vars` (имена привязанных переменных и стилей Figma) и `asset` (фото/иконка с форматом экспорта). Текст, перенесённый только шириной блока, приходит одной строкой с `lines:N`. По экземпляру (`INSTANCE`) `expand:true` раскрывает собственные слои с их id и оверрайдами; при обрезке дерева лимитом ответ несёт `truncated.droppedIds` — id обрезанных веток для дозапроса. С `format:"css"` вместо JSON приходит готовая вёрстка: HTML с flex-стилями, `var(--имя, #hex)` для переменных, список `:root` и `<img>` под ассеты. `figma_tokens` показывает имена переменных у цветов.

Везде, где нужен `id`, можно передать ссылку Figma с `?node-id=…`. `figma_node` по умолчанию
компактный (без значений по умолчанию) и с рамками `box`; отключается `compact:false`,
`boxes:false`.

## Создание и правка дизайна

| Инструмент     | Что делает                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `figma_create` | строит дизайн из JSON-спеки (по секциям); сам ставит фрейм в свободное место (справа от имеющегося; `direction:"below"`, `after`, `x`/`y`); ответ: id нод, замечания lint, скриншот |
| `figma_html_to_design` | HTML/CSS или динамический сайт по URL → редактируемые слои; размер viewport, ожидание рендера, импорт секции и `dry` без записи |
| `figma_edit`   | правки: update (в т.ч. массовые), move, delete, insert, duplicate, rename, reorder, restructure, компоненты |
| `figma_undo`   | откат последних N записей по журналу прогонов (хранится 8; считает по порядку, не по id)                                                           |
| `figma_guide`  | гайд по спеке и правилам дизайна — агенту стоит прочитать перед первым `figma_create`            |
| `figma_schema` | схемы редких частей (фигуры, группировка)                                                        |
| `figma_icons`  | поиск имён иконок (Lucide; Phosphor/Tabler/Material — если установлены)                          |
| `figma_styles` | создать/обновить цветовые и текстовые стили и переменные из токенов (дальше — `style:<имя>` в спеке); `remove:[…]` удаляет стили по имени |
| `figma_variants` | набор вариантов одним вызовом (кнопка Default/Hover/Pressed, FAQ Closed/Open, таб Active/Inactive): компоненты в «Components», реакции, замена одиночных копий экземплярами |; варианты можно строить из существующих блоков по их `id` (разные структуры — разные варианты); `dry:true` возвращает операции без записи
| `figma_componentize` | из повторяющихся блоков одной формы собрать компонент и экземпляры (тексты и фото сохраняются) |
| `figma_fonts`  | какие шрифты доступны (и какие начертания у семейства)                                          |
| `figma_focus`  | выделить ноды и показать их в Figma                                                              |

Готовые блоки — `chart`, `table`, `avatar`, `logo`, `qr`, `barcode` (нужен `bwip-js`), `mockup`, `map` — раскрываются в обычные редактируемые слои; данные блока меняются через `figma_edit` (`update` с полем блока). Картинки и SVG можно брать из проекта: `{"type":"image","path":"public/img/hero.jpg"}`. `figma_create`/`figma_edit` отказывают, если открытый файл сменился с прошлого вызова (или не совпал с аргументом `file`).

Иконки по имени превращаются в SVG на стороне MCP-сервера, стоковые фото (`image.query`)
скачиваются из интернета по ключевым словам (до 12 за вызов; свои байты — в `data`). Перед
записью плагин сохраняет версию файла в историю Figma, а копии затронутых блоков — на странице
«⟲ Vivi history» (по ним работает `figma_undo`).

Не нужна запись? `MCP_READONLY=1` убирает инструменты записи. Не нужны фото из интернета —
`MCP_NO_IMAGES=1`. Другие наборы иконок: `npm i --prefix ~/.vivi-figma @phosphor-icons/core`
(`@tabler/icons`, `@material-symbols/svg-400`) — тогда работают префиксы `ph:`, `tabler:`, `ms:`.

## HTML → Design

**Вручную, без ИИ-агента:** один раз запустите мост в фоне:

```bash
npx -y vivi-figma-mcp@latest bridge
```

После сообщения «Мост запущен в фоне» терминал можно закрыть. Повторный запуск
проверит уже работающий мост и не создаст второй процесс. Лог —
`~/.vivi-figma/bridge.log`. Без подключённых клиентов мост завершается через
15 минут; `IDLE_EXIT_MIN=0` отключает это поведение. После перезагрузки компьютера
команду нужно выполнить снова. Для отладки в текущем терминале:
`npx -y vivi-figma-mcp@latest bridge --foreground`.
Из исходников: `node server/cli.mjs bridge` (фон) или `npm start` (текущий терминал).

Затем
откройте плагин Vivi MCP в Figma, вставьте URL в поле «Адрес сайта», выберите
размер экрана и нажмите «Перенести в Figma». Есть пресеты телефона, планшета
и десктопа, свои размеры, ожидание элемента и загрузка контента прокруткой.
Готовый макет выделится на холсте. Если плагин уже был открыт, переоткройте
его после сборки; работающий мост тоже нужно перезапустить после обновления.

Один раз установите Chromium на машине MCP-сервера:

```bash
npx playwright install chromium
# Из исходников: npm run setup:browser
```

Передайте `figma_html_to_design` ровно один источник: `html` (строка), `path`
(UTF-8-файл внутри проекта) или `url` (http/https, в том числе localhost).
Варианты desktop/mobile создаются отдельными вызовами:

```json
{
  "url": "http://localhost:5173",
  "width": 390,
  "height": 844,
  "isMobile": true,
  "deviceScaleFactor": 2,
  "waitFor": "[data-ready]",
  "waitMs": 500,
  "name": "Главная — mobile"
}
```

`width`/`height` задаются **до загрузки**, в CSS-пикселях (по умолчанию 1440×900).
В форме плагина задаётся только ширина: импортируется вся страница по содержимому,
включая блоки ниже первого экрана. У MCP-инструмента необязательный `height`
задаёт только высоту окна браузера для `vh` и media queries и не ограничивает
длину макета.
Работают media queries и адаптивная логика JavaScript. `isMobile` включает
мобильный viewport, touch и Android Mobile user agent (`userAgent` можно переопределить);
для точной ширины мобильному сайту нужен обычный
`<meta name="viewport" content="width=device-width, initial-scale=1">`.
`deviceScaleFactor` меняет плотность растров, а не ширину CSS. `colorScheme:"dark"`
включает тёмную тему через prefers-color-scheme.

JavaScript включён по умолчанию; `waitFor` ждёт видимый CSS-селектор до 20 секунд,
`waitMs` добавляет до 10 секунд ожидания гидратации/данных. Снимок фиксирует текущее
состояние DOM; поведение приложения и авторизация не переносятся. Браузер запускается
в отдельной сессии без пользовательских cookies. `javascript:false` отключает скрипты.
Для URL сеть разрешена; для HTML/файла — только ресурсы проекта и data URL,
внешние запросы включаются явно через `allowNetwork:true`.
`scroll:true` прокручивает до 20 экранов для lazy-load и возвращает страницу наверх.

`selector:"main"` импортирует один блок; `dry:true` возвращает спеку и замечания
без подключения к Figma. До 600 слоёв за вызов, крупные страницы импортируйте
по секциям. Запись проходит обычные проверки открытого файла и поддерживает откат.

Текст, контейнеры и SVG остаются редактируемыми. Поддерживаемые Flex-контейнеры
становятся горизонтальным/вертикальным auto-layout: направление, gap, padding,
выравнивание, одинаковые flex-grow, stretch и перенос строк. CSS Grid становится
нативной сеткой Figma: фиксированные/fr-треки, строки, gap, span и именованные области.
Сложные раскладки (отрицательные/автоматические margin, перекрывающиеся ячейки,
непредставимое выравнивание) сохраняются координатами с замечанием в отчёте.
Переключение CSS-breakpoint внутри Figma не воспроизводится: для другой версии
экрана повторите импорт с нужной шириной. `autoLayout:false` отключает преобразование;
в форме плагина есть соответствующий переключатель в дополнительных настройках.
Изображения, CSS-фоны/градиенты, canvas и видео становятся растровыми слоями.
Непрозрачные фотографии сжимаются в JPEG; прозрачные фоны остаются PNG.
CSS-фоны и фотографии захватываются изолированно, без текста и оверлеев страницы.
SVG сохраняют размеры из CSS и пропорции `viewBox`; ссылки `<use>` на локальные
и внешние SVG-спрайты встраиваются в разметку иконки перед импортом.
При перекрытии соседних слоёв учитываются `z-index` и `order` Flex/Grid;
сложные перекрытия между разными ветками DOM могут требовать ручной проверки.
Абсолютные и фиксированные `::before`/`::after` с простым текстом или пустым `content`
переносятся отдельными слоями, включая их фоны и градиенты.
Недоступные в Figma шрифты заменяются с предупреждением. Неподдерживаемые CSS-эффекты,
потоковые и сложные псевдоэлементы, iframe и ограничения Shadow DOM отмечаются в отчёте.
Запуск Chromium ограничен 60 секундами; страницы с бесконечной загрузкой лучше
импортировать через `selector` и `waitFor`. Можно указать свой Chromium-совместимый
браузер переменной `VIVI_CHROMIUM_EXECUTABLE` (абсолютный путь к exe).
На Windows при отсутствии Chromium автоматически используется установленный Edge/Chrome.

## Экспорт изображений

Только внутри проекта агента — папки, из которой клиент запустил MCP-процесс (явно:
`MCP_PROJECT_DIR`). По умолчанию `<проект>/figma-exports`; можно передать абсолютный `dir`
внутри проекта. Корень диска и домашняя папка за проект не считаются, выход за пределы
проекта отклоняется. Дополнительные разрешённые папки — `MCP_EXPORT_ROOTS` (абсолютные пути
через `;`). Одинаковые по содержимому файлы сохраняются один раз.

## Настройки

Всё необязательно. Задаются переменными окружения — для `npx` проще всего в конфиге MCP:

```json
"vivi-figma": { "command": "npx", "args": ["-y", "vivi-figma-mcp"], "env": { "MCP_PROJECT_DIR": "D:/Projects/site" } }
```

При запуске из исходников можно использовать `server/.env` (образец — `server/.env.example`).


| Переменная         | По умолчанию                | Описание                                                    |
| ------------------ | --------------------------- | ----------------------------------------------------------- |
| `PORT`             | `8787`                      | порт моста (в манифесте плагина разрешён именно 8787)       |
| `MCP_PROJECT_DIR`  | рабочая папка MCP-процесса  | корень проекта: только внутри него пишутся картинки         |
| `MCP_EXPORT_ROOTS` | пусто                       | дополнительные разрешённые папки для экспорта               |
| `MCP_NO_AUTOSTART` | пусто                       | `1` — MCP-сервер не запускает мост сам                      |
| `MCP_READONLY`     | пусто                       | `1` — без инструментов записи (create/edit/undo)            |
| `MCP_NO_IMAGES`    | пусто                       | `1` — не скачивать стоковые фото (будут серые заглушки)     |
| `IDLE_EXIT_MIN`    | `15`                        | через сколько минут без клиентов мост завершается (`0` — никогда) |

Мост слушает только `127.0.0.1`. Запись в Figma идёт только через инструменты выше; файлы на диск
пишет лишь экспорт (внутри проекта).

## Разработка

```bash
npm run build       # сборка плагина (Figma подхватывает её сама)
npm run build:icons # пересобрать server/icons/lucide.json из lucide-static
npm run typecheck   # типы плагина
npm test           # юнит-тесты сервера и плагина
npm run smoke      # проверка собранного пакета (нужна перед публикацией)
```

Изменения `server/*.mjs` требуют перезапуска моста (или MCP-процесса).
