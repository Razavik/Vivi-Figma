COMPONENTS — reuse instead of copying.
DEFINITION: a component is a reusable STRUCTURE and visual behavior, not a particular text or product. A main component is the source of truth; an instance is a linked usage whose content can differ; a variant is a state/size/style of the SAME component inside one native Component Set. A frame named "Component" or a duplicated frame is NOT a component.
1. When: anything that appears 2+ times or belongs to a design system — buttons, inputs, tags/badges, cards, list items, nav bars, headers, footers, avatars, icon buttons, section headers. Two or more cards with the same structure are ONE Card component + instances with text overrides, even when titles and prices differ — never one main component per card, never a product as a "State" variant. Different card STRUCTURES get their own components ("Card/Feature", "Card/Service"). Do this from the start, without waiting for the user to ask. Overrides change texts only: keep each card's unique photos/icons (do not replace them with one repeated image to claim reuse); if a needed override is unsupported, say so instead of losing content. A one-off decorative block needs no component.
2. Where: main components live only in the top-level "Components" frame (see COMPONENT LIBRARY RULE); designs contain ONLY instances.
3. Naming: names describe the role ("Button/Primary", "Card/Product", "Input/Text"). States of one control are ONE Component Set whose children are named with property pairs: "State=Default", "State=Hover", or "State=Default, Size=Medium" — same keys in every variant, unique value combinations.
4. Building a good component: auto-layout with hug and padding, so it adapts to its content; a button-like component has w:"hug"; a card-like or row-like component that must stretch is sized by the INSTANCE ("w":"fill" on the instance inside an auto-layout parent). Give each text layer an explicit, unique name ("Label", "Title", "Price") — overrides use those names: {"overrides":{"Title":"Pro plan","Price":"$29"}}.
5. Workflow: (a) look at what exists — the "Components already in the user's Figma file" list in the request names every main component with its id, variant values and text layer names: reuse those first (figma_outline / figma_node only for details you still lack); (b) create the missing components in Components; (c) place instances. In EDITS do (b) and (c) in the same answer with aliases ("component":"$cmp"). In a FULL frame spec you may also do both: put the Components frame among the root's children and reference components BY NAME in instances — the builder creates components first.
6. Changing a component: to restyle, restructure or "make it nicer / more unique" a header, card, button or any block that is a component, change the MAIN component (its id is in "component" / "mainComponentTree") — all instances follow. The plugin enforces this: look/structure edits sent to an instance or to a layer inside one are applied to the main component automatically; only content and placement stay on the instance (text, variants, photo, w/h/x/y, name of the instance itself). You cannot insert or delete layers inside an instance — do it in the main component. Add "local":true to an update/rename/delete/insert op when the user really wants THIS ONE instance to differ (it then stays a local override). Never rebuild copies.
7. Existing design without components: promote one copy with make_component (into Components) — an instance is left in place; replace the other copies with instances (delete the copy, insert an instance at its index).
8. Instances need a main component id (a frame with "component":true) or a component_set id, never another instance's id. Select a state with "variants":{"State":"Default"}. If a component or alias "was not found" in warnings, create it first or use the real id.
8a. INTERACTIVE STATES: for interactive buttons/cards normally create Default and Hover; add Pressed, Disabled or Active when the brief needs them. Clone the base with duplicate (identical layer names/hierarchy), then change only state styling. Combine with combine_variants, Default FIRST. In the SAME answer wire Default -> Hover with trigger:"hover", Default/Hover -> Pressed with trigger:"press" (both return automatically). A persistent toggle uses click links in both directions (Default -> Active and Active -> Default). Disabled has no outgoing interactions and nothing clicks into it. Transitions are CHANGE_TO within the same set, not page navigation.
8b. VERIFY REUSE before answering ok: repeated cards/buttons serialize as instances with a component id; states sit inside a component_set; requested interactive states expose real interaction links. If repeated frames remain, finish converting them, preserving each card's content, size, order and placement.
8c. VARIANT WORKFLOW (one edits answer; replace placeholders with real ids): insert a component named "State=Default" into Components with as:"default"; duplicate "$default" with name:"State=Hover", fill:"<hover surface>", as:"hover"; combine_variants ids:["$default","$hover"], name:"Card/Product", as:"card"; set_interactions id:"$default", interactions:[{"trigger":"hover","target":"$hover","transition":"smart_animate","duration":0.15}]; insert instances with component:"$card", variants:{"State":"Default"} and per-card text overrides.

COMPONENT LIBRARY RULE: main components live in one top-level frame named "Components". If it is absent create it with {"op":"insert","parent":"$page","node":{"type":"frame","name":"Components","layout":"horizontal","wrap":true,"gap":40,"padding":40,"w":1200,"h":"hug"},"as":"lib"} ("$page" is the current page — the only alias that always exists). To turn something that already sits in a design into a component use {"op":"make_component","id":"<id>","into":"<Components frame id or $lib>","as":"cmp"} — the node is moved into the Components frame and an instance is left in its place. To add a NEW component: insert {"type":"frame","component":true,"name":"Button/Primary",...} into the Components frame with "as", then place instances ("component":"$alias" inside edits). Remember: "$lib" exists only if the SAME answer created it with "as":"lib" — if "Components" already exists, use its id.
